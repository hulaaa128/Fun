## 1. 背景与问题

### 1.1 为什么做

内部已经有品牌/IP 建设的诉求，但品牌形象目前**只活在 PPT、海报、周边里**，员工日常几乎接触不到，缺少一个「每天都在眼前」的高频触点。与此同时，员工桌面上散落着一堆各自为战的小工具（待办、消息提醒、公告），彼此没有统一入口，也没有品牌温度。

我们希望把这两件事合成一件：**做一只承载实用功能的品牌桌宠**。让品牌形象借由「有用」这件事，自然地进入员工的每一个工作日——不是靠强推曝光，而是靠「它帮我记事、帮我盯 @、帮我看公告」留下来。

### 1.2 核心洞察

- 纯曝光型的品牌吉祥物留存差：好看但没用，员工很快关掉。
- 纯工具型的效率软件没温度：有用但冰冷，无法承载品牌情感。
- **「实用为核、品牌为壳」** 才能同时拿到留存与品牌资产：先靠功能活下来，再靠形象记得住。

这也是本 PRD 与市面上常见「摸鱼桌宠 / 纯装饰吉祥物」的根本分野。

---

## 2. 产品定位与目标

### 2.1 定位

> 一只常驻桌面角落的品牌吉祥物，把「稍后处理 / 消息不漏 / 公告触达」这类高频办公需求收进一个有品牌人格的入口里。**核心价值是实用，品牌形象是让人愿意长期留着它的理由。**

### 2.2 目标（分层）

| 层级 | 目标 | 衡量 |
|---|---|---|
| 业务目标 | 让品牌 IP 成为员工日常高频触点 | 日活桌宠数 / 内部渗透率 |
| 产品目标 | 提供「不打断、不遗漏」的轻办公助手 | 功能使用率、次周留存 |
| 品牌目标 | 建立可延展、可周边化的统一 IP 形象 | 形象识别度、周边/表情包衍生 |

### 2.3 非目标（明确不做）

- 不做 IM / 聊天工具，只做消息的「提醒与收拢」，不承接回复。
- 不做重型任务管理（无项目、甘特、协作分配），只做个人「稍后处理」清单。
- 首版不做 Windows / 移动端（见第 11 节 Roadmap）。
- 不做游戏化养成系统（喂养、升级、金币），避免喧宾夺主稀释「实用」定位。

## 3. 目标用户与场景

### 3.1 用户画像

- **主力**：内部一线员工（研发、运营、产品、职能），macOS 办公，同时挂着京ME/IM、多个群、待办散落各处。
- **共性痛点**：
  1. 被打断时答应别人「晚点弄」，转头就忘。
  2. 群消息太多，被 @ 了没看见，红点又不敢乱清。
  3. 公司公告淹没在群里，重要信息触达率低。

### 3.2 典型场景

| # | 场景 | 桌宠的介入 |
|---|---|---|
| S1 | 开会/专注时被同事 IM 打断，答应「等下处理」 | 一键把这件事丢进桌宠的「稍后处理」，不打断当前专注 |
| S2 | 群里有人 @ 我，但当时在忙没看到 | 桌宠后台静默轮询，发现 @ 我后在气泡里列出候选，可「收下」转成待办或「忽略」 |
| S3 | 有空了，想清一清欠下的事 | 点开桌宠，从上往下按优先级领任务、打勾 |
| S4 | 公司/团队发了重要公告 | 桌宠气泡置顶展示公告卡片（后续版本） |
| S5 | 摸鱼间隙 | 桌宠的待机动画、节日彩蛋、表情反馈带来品牌陪伴感 |

## 4. 借鉴分析：LaterQueue 原型

本产品直接站在本仓库 **LaterQueue** 的肩膀上——它已经把「桌宠 + 实用功能」这条路走通并验证，是最佳的技术与体验蓝本。

### 4.1 已验证的能力（可直接复用）

| 能力 | LaterQueue 现状 | 复用价值 |
|---|---|---|
| 桌面宠物窗体 | 无边框、置顶、可拖动、半透明、多屏跟随；纯自绘 `paintEvent` 合成，解决了 Retina 白边 halo | 桌宠壳层直接沿用 |
| 待机/交互动画 | 上下浮动、悬停放大、点击跳动、随机眨眼、悬停「漏沙→翻转」沙漏动画 | 品牌形象换皮后的动画框架 |
| 稍后处理队列 | 本地 JSON 持久化，置顶/打勾/删除/清理，气泡面板按优先级排列 | 核心功能之一，几乎可原样保留 |
| 京ME @我 监控 | 后台 `QThread` 跑 `joyctl` 轮询（10 分钟/次），纯只读不清红点；冷启动基线防误报；连续失败才告警；候选可「收下/忽略」 | 核心功能之一，产品化后加分项 |
| 监控群管理 | 弹窗内搜群（异步 `joyctl chat group search`）、增删群、设置 @检测姓名 | 配置能力已完整 |
| 开机自启 | LaunchAgent plist 注册 | 常驻属性刚需 |
| 打包分发 | 一键 `build.sh` 打 `.app`，已处理图标、dylib、瘦身 | 内部分发链路现成 |
| 健壮性 | 全局 excepthook 写 `error.log` 并弹窗；原子写 JSON（`.tmp` + `os.replace`） | 稳定性基线 |

### 4.2 从原型到产品，要补齐什么

LaterQueue 是「一个人能用的工具」，要成为「品牌桌宠」还差：

1. **品牌 IP 形象**：当前是通用「沙漏小精灵」，需替换为专属品牌吉祥物（见第 5 节）。
2. **形象人格化**：问候语、状态文案、节日彩蛋等品牌语气层。
3. **公告/触达通道**：从「个人工具」扩展到「组织能对它推信息」。
4. **配置与引导**：首次启动引导、更友好的设置面板。
5. **可观测**：内部渗透与留存的埋点（匿名、见第 9 节）。

### 4.3 关键取舍（延续原型的克制）

原型有几处值得坚持的设计哲学，产品化时**不要破坏**：

- **只读、不打断**：`joyctl` 读消息不清京ME 红点；轮询在后台线程，绝不卡主线程。品牌桌宠同样不能变成「打扰源」。
- **防误报优先于灵敏**：冷启动只建基线不弹历史；偶发超时不报红，连续失败才告警。宁可晚一点，不要狼来了。
- **面板即真相**：打包成 `.app` 后看不到 stderr，所有状态（上次检查时间、失败告警）都在气泡里可见。

## 5. 品牌 IP 形象设计（需一并设计）

> 由于品牌形象尚不存在，本节给出**形象设计的方向与规范要求**，作为交给设计师的 brief，而非最终定稿。

### 5.1 设计目标

- **可识别**：一眼记住，剪影可辨。
- **可延展**：能出多种姿态/表情/节日皮肤，能周边化（贴纸、公仔、表情包）。
- **可动画**：结构适合做浮动、跳动、眨眼、情绪反馈等 2D 帧动画。
- **有职能感**：形象最好与「助手/记事/守护」的功能气质呼应（呼应「稍后处理 + 盯消息」的定位）。

### 5.2 形象要求（交付规范）

| 维度 | 要求 |
|---|---|
| 风格 | 扁平/半扁平，圆润亲和，避免过多细节（小尺寸下要清晰） |
| 主体尺寸 | 桌面显示宽约 130px（沿用 `PET_WIDTH`），需提供 @2x/@3x Retina 资源 |
| 状态帧 | 至少：待机、眨眼、开心（新增任务）、提醒（有 @/公告）、休息（无任务） |
| 情绪表达 | 通过表情/姿态而非文字弹窗，保持「不打扰」 |
| 配色 | 与品牌主色一致，需同时验证浅色/深色桌面下的可读性 |
| 边缘 | 透明背景 PNG，预乘 alpha；避免半透明软边导致的合成白边（原型已有解法可循） |

### 5.3 人格设定（Persona）

给桌宠一个内部人格，统一所有文案语气：

- **性格**：靠谱、省心的小助手；话不多但关键时刻在。
- **语气**：亲切、简短、不卖萌过度、不打官腔。
- **口头禅/文案示例**：
  - 新增待办：「记下啦，忙完再说～」
  - 发现 @我：「有人喊你，要收下吗？」
  - 清空队列：「都清完了，今天很棒。」
  - 检查失败：「刚才没连上，我再试试。」

### 5.4 可延展资产

- 节日/纪念日皮肤（春节、周年庆、大促）。
- 表情包 / 企业微信-京ME 贴纸。
- 线下周边（公仔、徽章、鼠标垫）。

## 7. 交互与视觉规范

### 7.1 交互原则（三条铁律）

1. **不打断**：任何提醒都是「桌宠身上的被动变化」（徽标、表情、气泡），绝不弹窗抢焦点、绝不发声打断（除非用户显式开启）。
2. **不遗漏**：该记的事、该提醒的 @，宁可延迟不可丢失；所有状态在面板内可查。
3. **不越权**：只读消息、不代替用户回复、不清红点、不动用户数据之外的东西。

### 7.2 主要交互

| 操作 | 行为 |
|---|---|
| 左键单击桌宠 | 展开/收起队列气泡 |
| 拖动桌宠 | 系统级拖动，落点记忆 |
| 右键桌宠 | 菜单：添加、显示/隐藏、拉回中央、管理监控群、立即检查@我、清除已完成、开机自启、退出 |
| 气泡内「收下」 | @候选转为待办插入队列顶部 |
| 气泡内「忽略」 | 丢弃候选且不再拉回 |

### 7.3 视觉

- 沿用原型的暖色系奶油底面板（`#fcf7ee` 系），换成品牌配色。
- 深色/浅色桌面均需验证桌宠与徽标对比度。
- 面板宽度、圆角、阴影延续原型质感（阴影用面板自身效果，桌宠窗体关闭系统投影以免白边）。

## 8. 技术方案

### 8.1 技术栈（沿用原型）

- **语言/框架**：Python 3 + PySide6（Qt）。
- **形态**：单文件应用为起点（`laterqueue.py` 的结构），打包为 macOS `.app`（`build.sh` 一键构建）。
- **持久化**：本地 JSON，`~/Library/Application Support/<AppName>/`，原子写（`.tmp`+`os.replace`）。
- **消息能力**：`joyctl` CLI（京ME），子进程读群，`.app` 内需回退绝对路径解析（原型 `_resolve_joyctl` 已实现）。
- **并发**：阻塞的 `joyctl` 调用一律放 `QThread` worker，信号回主线程处理文件写与 UI，主线程持有 worker 引用防 GC。

### 8.2 关键参数基线（可调）

| 参数 | 原型值 | 说明 |
|---|---|---|
| 轮询间隔 | 10 分钟 | 平衡时效与 joyctl 负载 |
| 首轮延迟 | 3 秒 | 避免拖慢启动 |
| joyctl 内部超时 | 90 秒 | 读群本就慢 |
| 子进程外层超时 | 120 秒 | 须大于内部超时 |
| 失败告警阈值 | 连续 2 次 | 偶发超时不报红 |

### 8.3 架构分层（产品化建议）

```
┌─────────────────────────────────────┐
│  壳层  Pet（窗体/动画/徽标/菜单）        │
├─────────────────────────────────────┤
│  UI    QueueBubble / 各配置弹窗         │
├─────────────────────────────────────┤
│  能力  队列 | @监控 Poller | 公告 | 人格 │
├─────────────────────────────────────┤
│  数据  本地 JSON（原子写）              │
├─────────────────────────────────────┤
│  外部  joyctl（只读） | 公告接口         │
└─────────────────────────────────────┘
```

产品化时建议把「品牌形象/文案/皮肤」抽成**资产配置**（图片目录 + 文案 JSON + 节日表），与逻辑解耦，方便设计侧独立迭代、无需改代码换皮。

## 9. 数据、隐私与合规

- **本地优先**：待办、监控配置、@候选全部存本地，不上云。
- **消息只读**：`joyctl` 仅读取，不发送、不清红点、不改动京ME 状态。
- **@检测边界**：仅在用户显式添加的监控群内检测，姓名由用户自设。
- **埋点匿名**：若做渗透/留存度量，仅上报匿名事件（启动、功能使用计数），不含消息内容、不含具体待办文本。**任何埋点需先过内部隐私评审。**
- **权限最小**：只申请常驻/自启所需的最小系统权限。

## 10. 度量指标

| 指标 | 定义 | 目标（示意） |
|---|---|---|
| 渗透率 | 安装桌宠人数 / 目标人群 | 试点团队 ≥ 40% |
| 次周留存 | 首启后第 7 天仍在用 | ≥ 50% |
| 功能触达 | 用过队列或 @监控的比例 | ≥ 60% |
| @监控转化 | @候选被「收下」比例 | 观测项，用于调灵敏度 |
| 品牌识别 | 抽样问卷「认得这个形象」 | 迭代观测 |
